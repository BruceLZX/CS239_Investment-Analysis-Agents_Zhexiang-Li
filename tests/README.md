# Tests

151 offline tests. They spend no tokens and need neither Rakazo nor a network:
- **SEC and Yahoo:** recorded responses in `fixtures/` stand in for the live services, with a synthetic 10-K page for the filing reader and synthetic filings and charts for the valuation snapshot.
- **The trace exporter and the dashboard:** a captured run in Rakazo's transcript format, built in `test_export_trace.py`.

Run them from `src/`:

```bash
.venv/bin/python -m pytest ../tests
```

| File | What it checks |
|---|---|
| `test_sec_edgar.py` | SEC EDGAR parsing: the CIK is padded and unknown tickers are rejected. The statements come from 10-K values under the current revenue concept, capped at the requested years, with growth, margins, free cash flow, debt and net cash worked out, and the latest quarter, year to date and trailing twelve months from the 10-Qs; the filings are its sources. Debt takes each component from the concept with the most recent data, and depreciation without amortization is labelled so. Filings are filtered by form; requests need a contact User-Agent. |
| `test_filings.py` | The filing reader: a filing's HTML becomes one block a line without its hidden XBRL or scripts; an item is its body, not its table-of-contents line; reading an item names the filing and makes it the source; keyword searches cover the whole filing; long items come a page at a time; a missing item lists the items there are; a 10-Q's item 2 is the discussion, not Part II's item 2. |
| `test_prices.py` | The price summary states exchange, currency and timestamp, the 52-week range and the change to the latest price over 1-12 months; skips missing closes; rejects unknown periods; reports API errors. The market backdrop is a source too, and a benchmark that fails to load is left out. |
| `test_valuation.py` | The valuation snapshot works out each multiple from figures it names; unknown debt leaves EV unknown, and a missing cover-page share count is approximated and said so; peers give a median and the company a premium or discount; the company is valued at its own fiscal year ends; every filing and price used is a source; a company that cannot be valued says why. |
| `test_case_file.py` | Starting a run creates the case file, keeps the request and marks the run active; reads without an active run explain how to start one; registering a location again reuses its source ID, and a source records who registered it and with which tool. The status summary leaves out bulky content and shows the scope, which analyst saved each packet, each part's latest revision and check, the parts still missing by owner, and what the latest review asked of whom and what has come in. A version snapshots the latest revision of each part; the memo fails review only after the third round; the review gate needs an approving review of that exact version (P7); tool calls are logged only during a run. |
| `test_memo.py` | The memo check, rule by rule: unregistered source IDs (N1); numbers without sources, ignoring dates, years, list numbers, filing names and URLs (N2); unlabelled company claims (N3); the rating evidence gate for listed and private companies (N4); internal working material and production wording (N6); the disclaimer and data-as-of date. Also, the citation pattern is the skill's. |
| `test_memo_parts.py` | The depth standard: the ten parts and their owners; a part written to the standard passes, and the Phase 1 memos' parts fall short of it; tables of figures need a Source column; the evidence gate reads the cited sources; private companies are held to the private standard; the scorecard needs six scores and their average; scenario probabilities add up to 100; one question and three takeaways; a part past its length target gets a note, not a problem; empty and vague phrases; team names and writing about the writing count as internal material (N6). Assembly adds the header, the cited sources and the disclaimer, and a version check covers the rules, missing parts and sentences repeated across parts. |
| `test_server.py` | The MCP server: every tool is listed with text-only results; calls are logged to the active run; data tools register what they retrieved, credited to the caller, and list the IDs to cite, even without a run to register in; error messages reach the model; ratings, verdicts, parts and analysts are validated; the scope sets the memo's header and each part's standard. A saved part comes back with its check and author; unknown and oversized parts are refused; parts come back whole, or the reader is asked for fewer; a version is a snapshot that never changes; the check covers one part or the whole memo; `deliver_memo` records the review gate and the check but never blocks; review items, one line each starting with their part, go to each part's owner, and a review must agree with its verdict; a part saved again and again gets a note. Each call over HTTP is credited to the agent whose endpoint it came in on; a packet saved after a review answers its evidence requests; packets too long for one result come back as a list; sources come a page at a time; client documents carry their confidentiality label; long results are cut where Rakazo would cut them. |
| `test_scenarios.py` | Each scenario file is complete and its documents exist; every must-never rule N1–N9 is exercised by some scenario. |
| `test_rakazo_client.py` | Signing in again replaces the saved Rakazo session; setting up the team archives the retired Research Analyst and gives each bot its own MCP endpoint and tool allowlist. |
| `test_run_scenario.py` | `--narrate` prints each delivery once, in time order; a final review that doesn't approve ends the run without a memo; a request of your own runs like a scenario without documents; a follow-up needs a finished run, marks the run live while the question is out, captures it again with the original outcome, and leaves the run as it was if sending fails. |
| `test_export_trace.py` | A captured run becomes a complete trace. Rule observations catch planted breaks of N1, N5, N7 and N9 (against an analyst's first-brief budget), messages to the user that give a draft's rating before delivery (N5) or name internal material (N6), parts saved by someone other than their owner (P32) and rounds beyond three (P9), over-long replies (P21) and packets that list more searches than were run. Memo parts, versions and the delivered memo's depth by part join the trace and its Markdown. Runs resumed after an approval card are merged, and approval cards appear as platform-guard events. Replayed history and duplicate replies are dropped, and private details stay out. Usage is summed per agent and priced for the hour of each call, the Markdown reads as a timeline, and `check_trace` names what is missing. A follow-up question appears in the timeline in the turn it started. |
| `test_model_costs.py` | Model-call costs: DeepSeek's peak hours, including an evening in Los Angeles; a peak call costs what Rakazo recorded and an off-peak call half; Flash has its own price, which its retired names share; a model with no listed price gets no cost here. |
| `test_dashboard.py` | The dashboard: a captured run shows each delivery once with its rule observations; a run counts as finished only once its outcome is written; each tool call is credited to the caller the server logged, or for older logs to the bot that could make it, with a short summary of what it asked for. Memo parts and whom each review asks reach the page. A live run reads conversation, status and cost from Rakazo, pricing each call for its hour, and says when Rakazo can't be read. Only this machine can reach the server, and a run starts once, only from a JSON request. A request typed on the page starts a run of its own; a follow-up goes to the latest run only once it has finished; the user's second message shows as a follow-up. |
