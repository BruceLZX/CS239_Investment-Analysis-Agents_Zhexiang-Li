# Tests

154 offline tests. They spend no tokens and need neither Rakazo nor a network:
- **SEC and Yahoo:** recorded responses in `fixtures/` stand in for the live services, with a synthetic 10-K page for the filing reader and synthetic filings and charts for the valuation snapshot.
- **The report:** hand-written sections that meet the skill's standard, for a fictional company, are in `report_samples.py`; PDF tests are skipped where WeasyPrint cannot find Pango.
- **The trace exporter and the dashboard:** a captured run in Rakazo's transcript format, built in `test_export_trace.py`.

Run them from `src/`:

```bash
.venv/bin/python -m pytest ../tests
```

| File | What it checks |
|---|---|
| `test_sec_edgar.py` | SEC EDGAR parsing: the CIK is padded and unknown tickers are rejected. The statements come from 10-K values under the current revenue concept, capped at the requested years, with growth, margins, free cash flow, debt and net cash worked out, and the latest quarter, year to date and trailing twelve months from the 10-Qs; the filings are its sources. Debt takes each component from the concept with the most recent data, and depreciation without amortization is labelled so. Filings are filtered by form; requests need a contact User-Agent. |
| `test_filings.py` | The filing reader: a filing's HTML becomes one block a line without its hidden XBRL or scripts; an item is its body, not its table-of-contents line; reading an item names the filing and makes it the source; keyword searches cover the whole filing; long items come a page at a time; a missing item lists the items there are; a 10-Q's item 2 is the discussion, not Part II's item 2. |
| `test_prices.py` | The price summary states exchange, currency and timestamp, the 52-week range and the change to the latest price over 1-12 months; skips missing closes; rejects unknown periods; reports API errors. The market backdrop is a source too, and a benchmark that fails to load is left out. |
| `test_valuation.py` | The valuation snapshot works out each multiple from figures it names; unknown debt leaves EV unknown, and a missing cover-page share count is approximated and said so; peers give a median and the company a premium or discount; the company is valued at its own fiscal year ends; every filing and price used is a source; a company that cannot be valued says why. |
| `test_case_file.py` | Starting a run creates the case file with its workflow, evidence and user-data-request records, keeps the request and marks the run active; reads without an active run explain how to start one; registering a location again reuses its source ID, and a source records what it weakens. The status summary leaves out bulky content and shows the scope and language, which workflow records are saved, each analyst's saved and missing sections and evidence, each section's latest revision and check, review items by severity and what the latest review asked of whom. A version snapshots the latest revision of each section; unfinished reviews are not rounds, and the report fails review only after the third; the review gate needs an approving review of that exact version (P7); tool calls are logged only during a run. |
| `test_memo.py` | The rules, one by one: unregistered source IDs (N1); figures without a source, judged per paragraph, list item and table row, ignoring headers, dates, years, small ordinals, filing names, component fences and URLs (N2); unlabelled company claims, in English or Chinese (N3); the rating evidence gate for listed and private companies (N4); internal working material and bot names (N6); the disclaimer; source IDs next to Chinese text. |
| `test_sections.py` | The fourteen sections fill the skill's template slots in order, each with an owner on the team; a section is found by key, number or title; the mandatory components sit where SKILL.md puts them; score weights add up to 100; ratings follow the company type; every playbook heading a section names exists. |
| `test_report.py` | The renderer: prose citations become tags with their source's confidence, table citations plain links that do not count as tags, and unregistered IDs stay unlinked; each of the fourteen component kinds renders to the template's classes, its text not counted as prose paragraphs; a component the renderer cannot read says how to write it. The report fills every placeholder (cover, composite-score meta, year), marks a missing section, lists each cited source with its link and confidence, the user data requests and the areas for further diligence, links a client document to sources/, and prints to PDF; folder and file names follow the skill's output contract; the report's language follows the request. |
| `test_qa.py` | The skill's seven QA scripts as ported, at their thresholds: a section written to the standard passes check_depth, and each floor, the six-tag limit, missing components and tables, shallow, vague and writing-about-writing phrases and the granularity markers fail it; numbers ignore source IDs and URLs; English paragraphs are not mistaken for copies and repeated sentences ignore CSS (the script's bugs). check_report names each missing component, counts Chinese scenario labels, needs P/E as a term and checks the composite score and the PDF; check_citations needs registered, linked IDs, also next to Chinese text; check_evidence passes a complete block with a one-character confidence, lets the prohibited-words field list them, fails thin or unsourced blocks, does not take "secondary" for a filing and needs a listed company's public-equity rows; the register needs 8 usable, 4 independent and 1 primary source; the workflow records need their gates, items, argued rows, numeric probabilities that add to 100, one question and seven red-team answers; an open rewrite plan fails the version stage; rewrite items resolve when their section is saved again; the delivery folder holds only sources/, one HTML and one PDF. |
| `test_profiles.py` | The nine bots: every bot's instructions fit Rakazo's 20,000-character limit; every tool a bot is given exists on the server; each writer gets the standards for exactly its own sections; only the Lead messages other bots and only researchers search the web; the analysts share the workflow and the writers' tools; the instructions name the components each section requires. |
| `test_server.py` | The MCP server: every tool is listed with text-only results, and structured arguments are spelled out inline, since Rakazo reads a field without a type as a string. Calls are logged and credited to the caller, over HTTP by endpoint; data tools register what they retrieved and list the IDs to cite, even without a run; source types are the skill's, and a client document points to the delivery folder's sources/. The scope records the report's language; playbooks are read by heading or listed when too long; workflow records come back with their checks; user data requests are kept for the report. An evidence block reports its gate, and the gate covers the caller's sections. A saved section comes back with its check and whether its evidence came first; unknown, oversized and broken sections are explained; sections come back whole or the reader is asked for fewer; a section saved again and again gets a note. The composite score is section 14's weighted average; the QA loop writes a rewrite plan for each failing section's owner; a version is rendered (HTML, PDF, Markdown), checked and never changes; ratings follow the company type. The review takes five passes, routes items to owners, needs items unless it approves, and reopens in the same round; delivery writes the skill's folder, records the gate and the final check, and never blocks; client documents carry their confidentiality label; long results are cut where Rakazo would cut them. |
| `test_scenarios.py` | Each scenario file is complete and its documents exist; every must-never rule N1–N9 is exercised by some scenario. |
| `test_rakazo_client.py` | Signing in again replaces the saved Rakazo session; setting up the team archives the retired Research Analyst and gives each of the nine bots its own MCP endpoint and tool allowlist; the IC Reviewer's thinking is capped (at high by default), never raised. |
| `test_run_scenario.py` | `--narrate` prints each delivery once, in time order; a final review that doesn't approve ends the run without a memo; a request of your own runs like a scenario without documents; a follow-up needs a finished run, marks the run live while the question is out, captures it again with the original outcome, and leaves the run as it was if sending fails. |
| `test_export_trace.py` | A captured run becomes a complete trace. Rule observations catch planted breaks of N1, N5, N7 and N9 (against a first brief's budget), a brief before the research plan (P33) and a version without a QA loop (P36); messages to the user that give a draft's rating before delivery (N5) or name internal material (N6); sections saved by someone other than their owner (P32) or drafted before their evidence (P34), Critical items answered with no new source (N11) and rounds beyond three (P9); the red-team review after the first review (P35); over-long replies (P21) and evidence blocks that list more queries than were run (N1); a delivery whose final check failed (P40). Sections, evidence, versions, reviews and the final check join the trace and its Markdown. Runs resumed after an approval card are merged, and approval cards appear as platform-guard events. Replayed history and duplicate replies are dropped, a transcript record holding a next-line character stays whole, and private details stay out. Usage is summed per agent and priced for the hour of each call, the Markdown reads as a timeline, and `check_trace` names what is missing. A follow-up question appears in the timeline in the turn it started. |
| `test_model_costs.py` | Model-call costs: DeepSeek's peak hours, including an evening in Los Angeles; a peak call costs what Rakazo recorded and an off-peak call half; Flash has its own price, which its retired names share; a model with no listed price gets no cost here. |
| `test_dashboard.py` | The dashboard: a captured run shows each delivery once with its rule observations; a run counts as finished only once its outcome is written; each tool call is credited to the caller the server logged, or for older logs to the bot that could make it, with a short summary of what it asked for. Sections, evidence blocks, review items and each version's rendered report reach the page. A live run reads conversation, status and cost from Rakazo, pricing each call for its hour, and says when Rakazo can't be read. Only this machine can reach the server, and a run starts once, only from a JSON request. A request typed on the page starts a run of its own; a follow-up goes to the latest run only once it has finished; the user's second message shows as a follow-up. |
